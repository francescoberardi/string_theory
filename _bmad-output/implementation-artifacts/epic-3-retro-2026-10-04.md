## Findings

### Aggregate Views

- **Architecture Delta (Real-Time Streams & Offline Ingestion):**
  - Introduced Serverpod real-time WebSocket communication layer via `BagEndpoint.bagUpdates()` and `BagChannels.forUser(userId)`, transmitting `BagStreamMessage` events directly to subscribers.
  - Integrated client-side reactive streaming: `BagBloc` subscribes to the bag updates stream and dispatches `BagStreamReceived`, performing in-place health score and court hour patches to `BagLoaded` without full page reloads or jarring UI flashes.
  - Implemented clean Strategy Pattern for health ingestion: `HealthSyncService` abstract domain interface, implemented by `NativeHealthSyncService` (iOS HealthKit / Android Health Connect) and `SimulatedHealthSyncService` (in-app 90-minute tennis workout generator for judges/web/desktop), routed dynamically via `HealthSyncResolver`.
  - Implemented resilient offline architecture: `OfflineSessionQueue` backed by `SharedPreferences` persistence and `SessionQueueStorage` interface. `BagBloc` applies instant 60 fps optimistic string decay via `DecayEngine.calculateHealth`, stores un-synced sessions with client-generated idempotency keys, and drains the queue automatically upon network reconnect via `client.connectivityMonitor`.
- **Duplication Map (Tenant Resolution Helper):**
  - `_resolveUserId(Session session)` is implemented identically in both `BagEndpoint` (`lib/src/endpoints/bag_endpoint.dart:14-41`) and `SessionEndpoint` (`lib/src/endpoints/session_endpoint.dart:12-39`).
  - *Rationale:* Serverpod 4.0.3 auth identities provide `UuidValue` identifiers. Both endpoints independently implemented deterministic integer mapping (hex parsing with 64-bit FNV-1a hash fallback).
  - *Action:* Logged to `deferred-work.md`; propose extracting a shared server utility helper `TenantResolver` to prevent drift across future endpoints (e.g. Story 4.1 `RestringEndpoint`).
- **God-Class & Size Growth (UI Growth Trend):**
  - `virtual_bag_screen.dart` expanded to 868 lines (+583 net lines). It coordinates bag listing, FAB menus, simulation triggers, detection buffering, post-frame SnackBar scheduling, and assignment modal orchestration.
  - `workout_assignment_sheet.dart` introduced at 861 lines. Contains the progressive disclosure accordion, preset duration chips, surface selectors, racquet choice tiles, and unstrung racquet safety validations.
  - `bag_bloc.dart` grew to 512 lines, orchestrating bag CRUD, sample seeder, fast-forward dev control, WebSocket streaming, session logging, and offline queue synchronization.
  - *Finding:* While well-tested and modularized with clear private methods, `virtual_bag_screen.dart` and `workout_assignment_sheet.dart` should undergo component decomposition in Epic 5 to maintain long-term maintainability.
- **Pattern Divergence (Conventions Followed):**
  - All Serverpod endpoints validate session authentication (`requireLogin => true`), enforce strict multi-tenant scoping (`userId`), wrap multi-row mutations in database transactions (`session.db.transaction`), and guarantee idempotency via database indexes.
  - All Flutter UI components adhere to Court Midnight design system tokens (`CourtMidnightTheme`).
  - Pre-existing pattern noted: `BagBloc` surfaces raw exception text (`'Failed to ...: $e'`) in SnackBars. Tracked in `deferred-work.md` to map to user-friendly domain messages.
- **Spec-to-Implementation Reconciliation (100% Met):**
  - **FR-11 (Automated Workout Ingestion):** Implemented in `NativeHealthSyncService` with 7-day query window and tennis workout filtering.
  - **FR-12 (Atomic String Job Updates):** Implemented in `SessionEndpoint._insertSession` transactionally incrementing `totalCourtHours` and recalculating health score via `DecayEngine`.
  - **FR-13 & ARCH-3 (Idempotency & Deduplication):** Enforced via unique database index `session_log_external_id_idx` on `externalWorkoutId`; re-sending an existing workout returns existing record with 0 hours added.
  - **FR-14 & ARCH-4 (Real-Time WebSocket Sync):** `BagChannels.forUser(userId)` broadcasts `BagStreamMessage` to active clients in $<300$ ms.
  - **ARCH-5 (Strategy Pattern):** Clean abstraction with `NativeHealthSyncService` and `SimulatedHealthSyncService`.
  - **NFR-2 & NFR-4 (Performance & Offline Resilience):** Sub-10 second match logging via 3-tap quick logger; persistent offline session queue with automatic background sync.

### Code Lenses & Hardening

1. **Concurrent Idempotency Race Handling (Story 3.1):**
   - *Finding:* In Story 3.1 review triage, concurrent syncs of the same `externalWorkoutId` racing past the initial find query triggered a `DatabaseUniqueViolationException` on insert.
   - *Disposition:* Fixed in commit `c62316c`. Caught unique violation on `session_log_external_id_idx`, rolled back the transaction without counting hours, and safely returned the winning record.
2. **Deterministic Idempotency Key Generation (Story 3.5):**
   - *Finding:* In Story 3.5 review triage, manual sessions with null `externalWorkoutId` generated an ID only when enqueued offline. If an initial online RPC committed on the server but dropped connection before the response reached the client, the offline retry generated a second key, bypassing deduplication.
   - *Disposition:* Fixed in commit `e1a8acc`. `BagBloc._onLogSession` generates a deterministic `externalWorkoutId` upfront prior to the initial RPC attempt.
3. **Web Platform Compiler Parity for Simulation IDs (Story 3.3):**
   - *Finding:* In Story 3.3, dart2js integer bitwise shifts on Flutter Web differed from the 64-bit Dart VM (`1 << 32` evaluates to 0 in JavaScript).
   - *Disposition:* Fixed in commit `f23526d`. Implemented web-safe integer generation and added Chrome browser test execution to GitHub Actions (`.github/workflows/tests.yml`).
4. **Safety Check for Unstrung Racquets (Story 3.4):**
   - *Finding:* In Story 3.4, attempting to log a session for a bag with only unstrung racquets allowed opening the assignment sheet and failing on submission.
   - *Disposition:* Fixed in commit `b90d2a9`. Added static `_explainIfUnloggable` helper warning the player to restring before logging court hours.
