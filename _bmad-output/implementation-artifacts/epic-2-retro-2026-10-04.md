## Findings

### Aggregate Views

- **Architecture Delta (Clean & Modular):**
  - Introduced pure Dart `DecayEngine` domain calculation logic with identical formulas in both `string_theory_server` (`lib/src/domain/decay_engine.dart`) and `string_theory_flutter` (`lib/domain/decay_engine.dart`).
  - Added background worker infrastructure via Serverpod's `DailyDecayFutureCall` (`lib/src/future_calls/daily_decay_future_call.dart`), registered in `server.dart`.
  - Added on-demand developer endpoints in `BagEndpoint`: `triggerDailyDecayNow(Session session)` and `fastForwardRacquetAge(Session session, {required int racquetId, int? days})`.
  - Decoupled `VirtualBagScreen` by extracting `RacquetCard` (`lib/widgets/racquet_card.dart`) and `RadialHealthGauge` (`lib/widgets/radial_health_gauge.dart`), resolving Epic 1 Retro Item 1.
  - State management maintains clean Unidirectional Data Flow: `FastForwardRacquetAge` dispatches to `BagBloc`, performing in-place state mutation for `BagLoaded` to avoid screen reloading or flashing.
- **Duplication Map (Shared Domain Tradeoff):**
  - `DecayEngine` is copied between `string_theory_server/lib/src/domain/decay_engine.dart` and `string_theory_flutter/lib/domain/decay_engine.dart`.
  - *Rationale:* In Serverpod projects without a dedicated shared Dart package, models in `string_theory_client` are regenerated automatically, preventing custom domain logic from living inside client-generated code. Both implementations are verified with comprehensive unit test suites ensuring strict parity.
  - Tracked in `deferred-work.md` for potential extraction into a dedicated shared package.
- **Size & Churn (Refactoring Win):**
  - `virtual_bag_screen.dart` was reduced by 310 lines (net), transitioning from a monolithic screen to composed widget components.
  - Total production and test footprint for Epic 2 is +3,999 insertions and -350 deletions across 35 files, with tests accounting for ~2,000 lines (>50% of changes).
- **Pattern Divergence (None):**
  - All Serverpod endpoints validate authenticated sessions, enforce tenant authorization, validate inputs, and utilize database transactions.
  - All Flutter UI components adhere to Court Midnight design tokens (`#121516` background, `#1A1E20` surface, `#C6F10E` volt accent, Barlow Condensed typography).

### Code Lenses & Hardening

1. **Negative Installed Tension Clamping & Boundary Test Isolation:**
   - *Finding:* In Story 2.1, negative installed tension values could result in inverted tension loss strings, and calendar boundary calculation relied on system timezone drift.
   - *Disposition:* Fixed in commit `ed3bdd1`. Clamped `effectiveTension = installedTensionLbs <= 0 ? 0.0 : installedTensionLbs` and parameterized `now` parameter in `calculateHealth`.
2. **Input Validation on Dev Control RPC:**
   - *Finding:* In Story 2.4 review triage, `BagEndpoint.fastForwardRacquetAge` accepted unvalidated integer values for `days`, permitting negative or zero shifts.
   - *Disposition:* Fixed in commit `728ab7a`. Added positive integer validation (`effectiveDays <= 0`) throwing a 400 `BagException`.
3. **Optimistic In-Place State Management in SettingsScreen:**
   - *Finding:* In Story 2.4, triggering fast-forward from `SettingsScreen` initially bypassed `BagBloc`, causing full-screen reloading flickers.
   - *Disposition:* Fixed in commit `728ab7a`. Wired `FastForwardRacquetAge` event through `BagBloc`, updating `BagLoaded.racquets` in-place and showing SnackBar feedback.
