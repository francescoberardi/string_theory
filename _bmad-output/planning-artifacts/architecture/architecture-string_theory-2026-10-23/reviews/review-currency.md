# Currency & Reality-Check Review — String Theory v1 (Firebase) spine

## Verdict

Most technology choices are current and exist as described. However, the spine has two blocking problems. First, the stack it lists cannot be resolved together: `fake_cloud_firestore` conflicts with the project's `equatable ^3.0.0`. Second, AD-10 depends on Firebase Extensions, which is deprecated and shuts down on 2027-03-31. Several AD-11 and AD-12 details also need naming, because the official docs a builder will follow are out of date for the 7.x / 0.5.x packages.

| F2 | **High** | AD-10, Paradigm, Stack | **The Firebase Extensions service is deprecated and shuts down on 2027-03-31.** Installed extensions keep running. | F3 | **Medium** | AD-11 step 4 | **The web persistence API exists, but the official docs show an API that has been removed.** The current Firebase "Enable offline data" page still gives the Flutter web snippet `db.enablePersistence(const PersistenceSettings(synchronizeTabs: true))`. `enablePersistence` was removed in cloud_firestore 6.0.0 ("remove deprecated functions") and does not exist in 7.1.0. The current API, confirmed in `cloud_firestore_platform_interface` 8.1.0 and `cloud_firestore_web` 5.8.0 source, is `FirebaseFirestore.instance.settings = const Settings(persistenceEnabled: true, webPersistentTabManager: WebPersistentMultipleTabManager());`. The provider names in the spine exist: `AndroidPlayIntegrityProvider`, `AndroidDebugProvider({debugToken})`, `ReCaptchaEnterpriseProvider(siteKey)` and `WebDebugProvider({debugToken})`. | F5 | **Medium** | AD-12, AD-9 | **`--dart-define=FLAVOR` alone does not switch Android's `google-services.json`.** On Android, `google_sign_in` 7.x (via `google_sign_in_android` 7.2.18) reads the web OAuth client from `google-services.json` when no `serverClientId` is passed. If one `google-services.json` is shared across a Dart-only flavor switch, a dev build gets ID tokens issued for the other project's web client, and `signInWithCredential` against the dev project fails. Crashlytics' Gradle plugin and Play Integrity are also tied to the Gradle-time config. The standard FlutterFire multi-project setup uses Gradle `productFlavors` (`--flavor dev\|prod`) with `flutterfire configure --android-out android/app/src/<flavor>/google-services.json`. Two smaller points: AD-9 leaves out `GoogleSignIn.instance.initialize()`, which must be awaited exactly once before `authenticate()`. | F6 | Low | AD-3 | **Firestore rules cannot check every element of a list.** `rules.List` has `size`, `hasAll/Any/Only`, `x[i]`, `x[i:j]`, `concat`, `removeAll`, `toSet` and `join`, but no iteration. Recursion is not allowed, and the limit is 1,000 expressions per request. Rules can therefore check `pastStringJobs` for `is list` and `size() <= 100`, but cannot enforce the "list of StringJob" shape on each element. ## Verified OK (claims the memlog did not mark verified)

- **Crashlytics has no web support:** the `firebase_crashlytics` 6.0.1 plugin declares only android/ios/macos, and the Crashlytics docs list Apple/Android/Flutter/Unity. AD-11's web skip is correct. The AD-4 "report to Crashlytics" path must go through the `lib/services` wrapper, which is a no-op on web.
- **Performance on web:** `firebase_performance` 0.12.1 declares web (`firebase_performance_web` 0.1.10+15). No deprecation was found. Test Lab and Extensions are the products being deprecated.
- **Remote Config:** `setDefaults`, `activate`, `fetch`, `fetchAndActivate` and `ensureInitialized` exist in 7.0.1, and web is supported.
- **google_sign_in 7.2.0:** `authenticate()` returns `GoogleSignInAccount`, `.authentication.idToken` is a nullable `String`, and the FlutterFire federated-auth docs pass only `idToken` to `GoogleAuthProvider.credential`. This matches AD-9, apart from the `initialize()` gap noted in F5.
- **firebase_auth 7.0.1:** `FirebaseAuth.signInWithPopup(AuthProvider)` (web-only) and `User.reauthenticateWithPopup(AuthProvider)` both exist.
- **FieldValue:** `increment(num)`, `arrayUnion(List)` and `serverTimestamp()` exist in 7.1.0, which also adds `minimum`/`maximum`. Nested dot-path updates are standard.
- **fake_cloud_firestore 4.4.0 (setting aside F1):** it implements `WriteBatch` (`MockWriteBatch`), `increment` on dotted nested paths (`_findNestedDocumentToUpdate`), and `arrayUnion` with deep equality for map elements. It accepts `cloud_firestore >=6.7.1 <8.0.0`. Caveats: it doesn't simulate offline queuing, it doesn't reject `serverTimestamp` inside arrays, and it doesn't evaluate rules on batches or timestamps. Those AD-5 / AD-3 constraints must be tested against the emulator.
- **delete-user-data configuration:** comma-separated Firestore paths using `{UID}` and the `recursive` delete mode are still current. Its future is the problem (F2).

## Not confirmed in this pass

- **AD-5 offline behaviour of transforms:** whether `FieldValue.increment` on `currentStringJob.hoursPlayed` and `arrayUnion` of maps inside a `WriteBatch` or `update` apply locally and queue while offline, under persistence on both Android and web, could not be fetched from the docs. The relevant pages were truncated. This is consistent with SDK latency-compensation behaviour and with the memlog's verified "batched/plain writes queue". Recommend one emulator test with the network disabled (`disableNetwork()`, write, `enableNetwork()`, assert the server state) in the first repository story.
